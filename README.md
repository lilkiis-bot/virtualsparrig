# OCTAGON — 카메라 MMA 타격 스파링

HTML, CSS, ES Modules로 만든 1인칭 3D 타격 스파링 앱입니다. Three.js, MediaPipe Pose Landmarker, PeerJS를 사용합니다. 앱의 라이브러리·WASM·자세 인식 모델이 `vendor/`에 포함되어 있어 빌드나 npm 설치 없이 GitHub Pages에 배포할 수 있습니다.

## 빠르게 실행

Node.js 20 이상에서 프로젝트 폴더를 열고:

```sh
node tools/serve.mjs
```

브라우저에서 **http://localhost:4173**을 여세요. `npm start`도 같은 명령입니다. `index.html`을 더블클릭한 `file://` 주소는 ES Modules·카메라 제약 때문에 지원하지 않습니다.

카메라 없이 **터치로 체험하기**를 누르면 즉시 게임에 들어갑니다. 카메라를 연결하면 실제 손·발 동작으로 조작할 수 있습니다.

## GitHub Pages에 올리기

1. 새 GitHub 저장소를 만들고 **이 폴더 안의 파일과 폴더**를 저장소 최상위에 올립니다. `index.html`, `src/`, `vendor/`가 같은 위치에 있어야 합니다. ZIP 파일 하나를 그대로 올리는 방식은 실행되지 않습니다.
2. 저장소 **Settings → Pages → Build and deployment → Source**에서 **Deploy from a branch**를 고릅니다.
3. `main` 브랜치와 `/(root)`를 선택하고 저장합니다.
4. 배포가 끝나면 표시되는 `https://계정.github.io/저장소/` 주소로 접속합니다. 아이폰·아이패드도 이 **HTTPS 주소**를 여세요.

자동 테스트를 포함한 배포를 원하면 Source를 **GitHub Actions**로 바꾸고, 포함된 `.github/workflows/pages.yml`을 사용하세요. 두 방식 중 하나만 선택하면 됩니다. 상대 경로를 사용하므로 저장소 이름을 바꿔도 동작합니다. GitHub Pages는 별도 설치 없이 정적 파일을 제공합니다. 실제 저장소 생성·업로드·공개 배포는 이 프로젝트에서 수행하지 않았습니다.

## 포함된 게임 기능

- 붉은 반투명 머리·몸통·손·발로 구성된 3D 상대와 옥타곤.
- 내 손의 1인칭 표현, 발을 들거나 킥할 때 내 발 표시.
- AI 3단계: 루키 / 파이터 / 챌린저. 상대 공격 예고, 가드, 회피.
- 카메라 팔 뻗기·회수로 펀치, 발 들어 뻗기로 킥. 속도·관절 신뢰도·재입력 제한 적용.
- **한 손이라도 얼굴 영역을 가리면 모든 펀치 피해가 0**. 머리 킥도 가드 가능, 몸통 킥은 거리 회피 필요.
- 머리를 좌우로 이동하거나 숙이면 머리 공격 회피. 뒤로 물러나 사거리 밖이 되면 회피.
- 스태미나 소비와 회복, 체력, 적중·방어·회피·정확도 기록.
- **5분 × 3라운드 / 5분 × 5라운드 / 3분 × 3라운드 / 3분 × 5라운드**.
- 라운드 사이 15초 휴식. 체력 18 회복(최대 100), 스태미나 완전 회복.
- 일반 KO와 **퍼펙트 샷 KO**, 경기 종료·재경기. 마지막 라운드 종료 시 라운드 점수로 판정.
- 화면 고정 터치 버튼(휴대폰), 키보드, 효과음, 전체 화면(지원 기기), 화면 꺼짐 방지(지원 기기).

### 퍼펙트 샷 KO 판정

다음 조건을 **모두** 만족한 머리 타격은 남은 체력과 관계없이 즉시 KO입니다.

1. 상대가 가드 중이 아니고, 공격이 회피되지 않았음.
2. 타격 중심과 상대 머리 중심의 가로·세로 차이가 각각 0.085 / 0.09 게임 단위 미만.
3. 양쪽의 후퇴 거리 합계가 0.28 미만.
4. 공격 시작 시 스태미나가 65 이상, 공격 강도 0.9 이상.
5. 상대 공격의 도달 시점과 내 공격의 도달 시점 차이가 125ms 미만인 카운터.

카메라의 공격 강도는 **추정 관절 속도**에서 계산합니다. 실제 힘을 측정하지 않습니다. 터치·키보드 공격 강도는 0.96입니다. 일반 피해로 체력이 0이 되어도 KO입니다. 라운드별 더 많은 피해를 준 쪽이 10점, 반대가 9점이며 동률은 10:10입니다. 실제 MMA 심판 판정의 재현이 아닌 게임용 규칙입니다.

## 카메라 사용

1. 스마트폰이나 태블릿을 고정하고, 머리부터 발끝까지 화면 안에 들어오게 섭니다.
2. **카메라 연결**을 누르고 권한을 허용합니다. 처음에는 로컬 모델을 읽는 시간이 필요합니다.
3. 정면을 보고 편안히 선 자세를 2초간 유지합니다. 관절만 표시되는 미리보기에서 상태를 확인합니다.
4. 보정 완료 후 스파링 시작. 감도 슬라이더로 펀치·킥 속도 문턱을 조절합니다.
5. 위치나 카메라 각도가 달라지면 **기준 자세 보정**을 다시 누릅니다.

카메라 원본 프레임은 기기 내부의 MediaPipe에만 전달합니다. 녹화·업로드·상대방 영상 전송이 없습니다. 온라인에는 손·발의 추정 좌표, 가드·회피 상태, 게임 이벤트만 전송합니다. 미리보기도 실제 영상이 아닌 관절 그림입니다. 브라우저의 카메라 표시등은 실제로 카메라가 사용 중이므로 켜집니다.

추적이 끊기면 자동 일시 정지합니다. 프레임 안으로 돌아와 계속하기를 누르세요. 카메라 끄기는 MediaStream 트랙과 Worker·모델을 해제합니다. 마이크는 요청하지 않습니다.

## 4자리 코드 온라인 대전

1. 두 플레이어가 각각 앱을 열고 **1:1 온라인**을 선택합니다.
2. 한 명이 **방 만들기**를 누릅니다. 이 플레이어가 호스트로서 체력·충돌·승패 판정을 맡습니다.
3. 다른 한 명은 **방 참가하기**에서 숫자 4자리 코드를 입력합니다.
4. 방장이 경기 형식을 선택합니다. 두 명이 **대전 준비**를 누르면 시계·지연 측정 후 시작합니다.
5. 재경기는 다시 준비하기를 누른 후 두 명 모두 준비합니다. 방을 나가거나 10초 동안 응답이 없으면 경기를 종료합니다.

한 방에는 두 명만 들어갑니다. 4자리 코드는 빠른 매칭용이며 비밀번호·인증 수단이 아닙니다. 공개 랭킹이나 금전이 걸린 경쟁 시스템을 위한 부정행위 방지는 제공하지 않습니다.

### 지연 보정 방식

- WebRTC DataChannel로 연결하고 PeerJS는 연결 정보 교환에 사용합니다.
- 게임 이벤트와 자세 데이터를 별도 채널로 전송합니다. 자세는 약 25Hz, 호스트 스냅샷은 약 12.5Hz.
- Ping/Pong의 송수신 시각으로 RTT·시계 차이·지터 측정.
- 상대 화면은 50–180ms의 적응형 버퍼로 보간. 오래된 자세 순번은 폐기하고 송신 버퍼가 밀리면 자세 패킷을 생략.
- 호스트가 양쪽의 최근 1.5초 자세 기록을 보관하고 타격 도달 시점의 가드·위치를 조회.
- 공격 타임스탬프 역산 및 판정 대기는 최대 250ms까지 제한. 양쪽에 같은 판정 대기 적용.
- 중복 공격 ID, 비정상 좌표, 공격 간격, 스태미나를 호스트에서 검증.

지연을 **없애는** 기능은 아닙니다. 400ms를 넘는 연결은 화면에 안내합니다. 느린 Wi-Fi나 이동통신에서는 실시간성이 떨어질 수 있고, P2P 호스트는 신뢰가 필요합니다.

### 서버가 필요한가요?

기본 설정은 **공개 PeerJS 시그널링 서버**를 사용합니다. 따라서 사용자가 직접 게임 서버를 배포하지 않아도 연결을 시도할 수 있지만, 외부 서비스는 필요합니다. GitHub Pages 자체는 WebSocket·TURN 서버를 실행하지 않습니다.

통신사·기관 네트워크의 NAT/방화벽 때문에 직접 연결이 막힐 수 있습니다. 모든 네트워크에 가까운 연결 성공률이 필요하면 **TURN 릴레이**를 운영하거나 서비스에서 발급받은 단기 자격 증명을 `config.js`의 `iceServers`에 공급해야 합니다. 기본 앱에는 비용이 발생하는 TURN 계정이나 서버를 임의로 넣지 않았습니다. 단기 인증 발급을 자동화하려면 별도 백엔드가 필요합니다.

자체 시그널링 서버를 원하면 `server/`가 준비돼 있습니다.

```sh
cd server
npm install
npm start
```

공개 운영에서는 HTTPS/WSS 리버스 프록시 뒤에 배치하세요. 이 서버는 방 매칭·연결 중개용이고 영상 처리나 전투 판정을 실행하지 않습니다. `config.js` 예:

```js
window.OCTAGON_CONFIG = {
  peer: { host: 'signal.your-domain.com', port: 443, path: '/octagon', secure: true },
  iceServers: [
    { urls: 'stun:stun.l.google.com:19302' },
    { urls: 'turns:turn.your-domain.com:5349', username: 'SHORT_LIVED_USER', credential: 'SHORT_LIVED_TOKEN' }
  ]
};
```

브라우저 설정은 누구나 읽을 수 있으므로 관리용 API 키·장기 비밀 키를 넣지 마세요. TURN 운영 설정과 HTTPS 인증서는 사용자의 서버 환경에 맞게 준비해야 합니다.

## 지원 범위와 확인된 한계

- 최신 Chrome / Safari 및 WebGL 2, WebAssembly, WebRTC 지원 브라우저를 대상으로 설계했습니다. MediaPipe는 CPU Worker를 우선 쓰고 초기화 실패 시 메인 스레드 GPU/CPU로 전환합니다.
- 한 대의 RGB 카메라로 추정한 3D 좌표입니다. 전용 깊이 센서 수준의 거리·충돌 정확도는 아닙니다. 후퇴는 어깨 너비와 몸통 길이 변화로 추정하므로 상체 회전·가림·조명에 영향을 받습니다.
- 펀치는 팔의 뻗음·속도, 킥은 발의 들림·속도·다리 뻗음으로 분류합니다. 정밀한 주먹 모양, 타격 부위별 손가락 접촉, 모든 훅·어퍼컷·회전 킥의 구분은 지원하지 않습니다. 공격 시작 시 상대 위치를 향하도록 게임에서 조준합니다.
- 카메라 영상의 프레임률·발열·성능에 따라 인식 속도가 달라집니다. 구형 기기에서는 메인 스레드 대체 경로로 프레임률이 떨어질 수 있습니다.
- 자동 브라우저 검증은 Windows Chrome에서 진행했습니다. 휴대폰/태블릿 **화면 크기**와 가상 카메라는 검증했지만, 실제 iPhone/iPad의 카메라·터치·네트워크와 실제 사람의 펀치·킥은 실기기 검증이 남아 있습니다. 모든 스마트폰에서 무오류를 보장하지 않습니다.

## 테스트와 파일 구조

```sh
node --test tests/*.test.mjs
```

한 손 가드, 피격, 좌우·후방 회피, KO, 네 형식의 전체 라운드 진행, 일시 정지, 지연 보정, 공격 중복 제한, 자세 보정과 펀치 검출 등을 검증합니다. 상세 브라우저 점검 결과는 `VERIFICATION.md`에 있습니다.

```text
index.html / style.css       화면 및 반응형 스타일
config.js                   공개 시그널링 / ICE 설정
src/main.js                 게임 흐름, 입력, 화면
src/arena.js                Three.js 옥타곤·캐릭터
src/combat.js               판정·라운드·KO·과거 자세 기록
src/gestures.js             보정·펀치·킥·가드·회피
src/tracking.js             카메라 수명 주기·모델 대체 경로
src/pose-worker.js          자세 인식 Worker
src/network.js              P2P·시계 동기화·보간
src/audio.js                로컬 합성 효과음
vendor/                     고정 버전 라이브러리·WASM·모델
tools/                      로컬 HTTP 서버·에셋 복구
tests/                      게임 / 인식 규칙 테스트
server/                     선택적 자체 시그널링 서버
.github/workflows/pages.yml 선택적 GitHub Pages 자동 배포
```

`vendor/`를 지웠다면 `node tools/setup-assets.mjs`로 같은 버전의 파일을 복구할 수 있습니다. 해당 명령은 인터넷이 필요합니다.
